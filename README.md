# Miro Inbox Bot

Telegram-бот-инбокс: любое текстовое сообщение, отправленное боту, превращается
в стикер на доске Miro. Разбор стикеров (по задачам/целям) — отдельный, ручной
шаг, которым занимается человек.

## Как это работает

GitHub Actions по расписанию (`.github/workflows/inbox.yml`, каждые ~5 минут,
плюс ручной запуск через "Run workflow") запускает `bot.py`, который:

1. запрашивает у Telegram новые сообщения (`getUpdates`) начиная с сохранённого
   смещения (`state/offset.txt`);
2. для каждого текстового сообщения создаёт стикер на доске Miro через API
   (`POST /v2/boards/{board_id}/sticky_notes`), размещая его в следующей ячейке
   сетки (позиция хранится в `state/position.json`);
3. отвечает пользователю в Telegram "✅ Добавлено на доску";
4. коммитит обновлённые файлы состояния обратно в репозиторий.

Состояние (`state/`) специально хранится в самом репозитории — это самый
простой способ пережить то, что каждый запуск GitHub Actions стартует с нуля.

## Настройка

В репозитории (Settings → Secrets and variables → Actions) нужно добавить:

| Secret | Обязателен | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `MIRO_ACCESS_TOKEN` | да | токен приложения Miro (scopes `boards:read`, `boards:write`) |
| `MIRO_BOARD_ID` | да | ID доски, например `uXjVHYvaJTU=` (из ссылки на доску) |
| `ALLOWED_CHAT_ID` | нет, но рекомендуется | numeric chat_id — если задан, бот реагирует только на сообщения из этого чата |

### Как узнать свой `ALLOWED_CHAT_ID`

1. Напиши боту любое сообщение.
2. Один раз вручную запусти workflow без секрета `ALLOWED_CHAT_ID`
   (Actions → Miro Inbox Bot → Run workflow) — сообщение уйдёт на доску от кого угодно, кто напишет боту.
3. Либо проще: напиши https://t.me/userinfobot — он сразу покажет твой числовой id.
4. Добавь secret `ALLOWED_CHAT_ID` с этим числом.

Без этого secret'а бот будет создавать стикеры от сообщений любого, кто найдёт
username бота — стоит задать его сразу после первого теста.

## Ограничения v1

- Только текстовые сообщения (фото/файлы/голосовые игнорируются).
- Сетка стикеров фиксированная (6 колонок), без учёта конкретного фрейма на доске.
- Проверка раз в ~5 минут — не мгновенно (ограничение расписания GitHub Actions).
